# Уроки (дополнять после каждой работы)

## Доступ и окружение

- Публичная папка Google Drive читается без входа: список — `https://drive.google.com/embeddedfolderview?id=<FOLDER_ID>`,
  файл — `https://drive.usercontent.google.com/download?id=<FILE_ID>&export=download&confirm=t`.
  В облачной среде нужны хосты `drive.google.com` и `drive.usercontent.google.com` (создано окружение `searchparts`).
- Загрузить файл обратно в Drive без OAuth-доступа нельзя — отдавать файлы пользователю, он загружает сам.
- iPhone-фото приходят в HEIC: `pip install pillow-heif`, затем `ImageOps.exif_transpose`.

## Интернет-проверка

- Окружение `searchparts` с 2026-11-12 имеет полный доступ в интернет (нужен для каталогов, схем и фото деталей).
- `curl` видит изменение сети сразу, а встроенный WebFetch/web-fetch-агент может ещё некоторое время отвечать
  `ENOTFOUND` — тогда проверять доступность через `curl`.
- Сайты с защитой от ботов (403 на обычный запрос, например duallane.com, skandix.de) не обходить подменой
  заголовков — брать данные из поисковой выдачи или других источников и прямо говорить, что страница закрыта.
- Без марки и узла поиск «болт по фото» даёт только похожие универсальные болты; 200 источников набирать
  бессмысленно — сначала получить марку/узел/замеры, потом искать по каталогу по VIN.

## Чтение визиток

- 4 визитки на фото: резать по квадрантам с перекрытием 56 %, чтобы карточка на границе не обрезалась.
- Мелкие цифры читать только через лупу (`zoom.py`, `zoomx.py` с контрастом), а не по общему кадру.
- Надёжный контроль — **слепое** повторное чтение (без доступа к базе) и автоматическое сравнение по
  номерам, email, сайтам, названиям, WhatsApp. Каждое расхождение — смотреть по фото самому.
- Сравнивать только контакты, у которых прочитаны **все** позиции: частичное чтение даёт ложные тревоги
  (так было с Drive Next: вторая визитка ещё не была прочитана).
- Типичные ошибки первичной обработки: перепутаны лицевая и оборотная стороны в паре фото; значок WhatsApp у
  группы номеров не учтён; карандашный/рукописный номер упомянут в заметке, но не внесён; последняя рукописная
  цифра (8/9) прочитана уверенно, хотя неоднозначна.
- Тип номера (телефон / мобильный / факс) определять по значку через лупу: значок настольного телефона легко
  принять за факс, и рабочий номер выпадает из списка телефонов.
- Ошибочные «исправления» агентов тоже бывают: агент снял отметку WhatsApp там, где значок стоит у имени над
  номерами. Решение принимать только по фото.

## QR-коды

- `zxing-cpp` быстрый (~0,6 с на фото) и находит больше, чем OpenCV `QRCodeDetector` (медленный, ничего не дал).
- Тяжёлые переборы предобработки на трудных QR долгие. Пользователь попросил **пропускать расшифровку QR** —
  по умолчанию не запускать, только по просьбе. Если значения уже получены попутно — вносить с пометкой.

## Агенты и процессы

- Прерывание пользователем останавливает и фоновых агентов. Агенты должны писать результат пошагово
  (после каждого фото), чтобы потом дочитать только недостающие позиции.

## Репозиторий

- Репозиторий публичный: не коммитить телефоны, имена, email людей с визиток, фото и ссылку на папку Drive.
  Правки с конкретными номерами живут в `audit_log` самой базы.
